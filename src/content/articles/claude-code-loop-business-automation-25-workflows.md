最近 AI 圈在傳一份清單，叫 Claude Loop Library，收錄了25種可以自動排程跑的商業工作流。原始來源是 X 上一個叫 Machina 的人，思路照 Karpathy 提出的 agent 食譜，中文媒體 blocktempo 也做了整理。

我研究了這份清單，也把 Claude Code 的 /loop 功能查清楚。這篇是研究跟評估，不是實測數據，重點放在：這套東西到底怎麼運作，還有誰真的用得到。

--

## /loop 到底是什麼

先講清楚 /loop 這個功能。它不是跑一次就結束，是讓一個指令或一段任務照你設的節奏重複跑，一直跑到完成或你喊停。

它有兩種模式。

第一種是固定間隔。你指定多久跑一次，語法像 /loop 5m 加上要跑的指令，意思是每5分鐘跑一次。間隔可以寫30秒、5分、1小時。

第二種是自我調速。你不給間隔，讓模型自己判斷下一次什麼時候該醒來跑，根據任務進展調整節奏。這種比較聰明，適合盯著一件事直到搞定的情境。

<blockquote class="geo-quote" itemscope itemtype="https://schema.org/Quotation">
<p itemprop="text">Claude Code 的 /loop 是排程循環功能，讓指令或任務重複跑到完成或喊停。兩種模式：固定間隔（/loop 5m 每5分鐘跑一次）跟自我調速（模型自己決定下次何時跑）。適合在對話裡盯一件事反覆做到好。</p>
</blockquote>

--

## 有個省錢細節要知道

自我調速模式的運作原理是，每跑完一輪，模型自己排下一次的鬧鐘，帶著同一個任務再跑，直到達成條件或你喊停。

這裡有個成本細節。對話有一個5分鐘的快取，如果兩次跑的間隔超過5分鐘，快取會失效，下次啟動就比較慢比較燒錢。

所以節奏要嘛抓5分鐘以內（快取還在），要嘛乾脆拉到20到30分鐘以上（一次燒得值得）。最爛的選擇是卡在剛好5分鐘，兩邊好處都拿不到。

--

## /loop 跟 cron 排程不一樣

這個差別很重要，很多人會搞混。

/loop 是在你這個對話 session 裡重複跑，你這個 session 開著它才跑。

cron 排程是另一回事，那是雲端 agent 到你設的時間自己起來跑，就算你電腦關了也會跑，跑完把結果送你。

判斷很簡單：要真正無人值守、定時自動跑（像每天固定時間發報表），用 cron 那種雲端排程。要在對話裡盯著一件事反覆做到好（像 debug 一個問題、掃語意空缺掃到夠），用 /loop。

## 那25種工作流在做什麼

這份 Claude Loop Library 把25種工作流分成四類。

行銷內容類9種，包含答案引擎空缺識別、競品內容追蹤、品牌聲量監控、廣告疲勞自動出草稿、內容大綱佇列這些。

產品類3種，品牌提及的功能雷達、App商店評論挖掘、流失點文案迴圈。

營運類6種，收件匣轉決策、月結對帳準備、SOP漂移偵測、提案草擬、KPI異常監控、未付款催收。

研究決策類7種，過夜情報刷新、法規來源摘要、難度升級佇列、覆盤、影子測試這些。

## 一個關鍵提醒：不會累的模型也不會自己停

這套清單預設搭配 Fable 5 這種高階模型跑，因為它擅長長時間專注不分心。

但這正是要小心的地方。Fable 5 輸入每百萬 token 10美元、輸出50美元，是 Opus 4.8 的2倍。它不會累，也不會自己停。

所以每個 loop 一定要設兩個東西：預算上限，跟明確的停止條件。

實務做法是模型分工。便宜的活先派小模型（Haiku、Sonnet），只有真的難的任務才升級到 Fable。這跟「不要用最貴的模型做 grep 就能做的事」是同一個道理。

## 誰真的用得到

對已經在用 Claude Code、也在做自動化的人來說，這份清單不是新知識，是一份把已有能力排程化的現成菜單。

像廣告代操盯 KPI 異常、自媒體經營掃答案引擎空缺、一人公司自動處理月結對帳跟未付款催收，這些工作流每一個都對得上真實的商業痛點。

我研究這份清單最大的收穫是：自動化的門檻不在技術，在紀律。選對要自動化的重複工作，設好停止條件，把便宜的活交給便宜的模型，飛輪才轉得起來又不燒錢。
