每次開電腦，第一件事是開終端機，然後開五六個視窗。

每個視窗交代一件事。第一個去拉昨天的廣告數據。第二個找素材庫有哪些商品還沒有圖。第三個繼續上次寫到一半的工具頁面。第四個整理昨天的會議記錄。第五個跑上週排程還沒完成的任務。

同時進行，不用等。

--

大多數人用 AI 的方式是一問一答。問一個問題，等答案，再問下一個。

這樣沒問題，但你等著 AI 的時候，時間在空轉。

三個月前我開始改成並行：把一天要做的事情先拆開，找出哪些可以同時跑，每個開一個視窗。等 Claude Code 在執行的時候，我去看另一個視窗的進度。

節奏變了。我在指揮，不是在等。

--

真正讓這套東西跑起來的，是 skill 系統。

每件重複的任務，我會整理成一個 .md 檔，記錄這件事怎麼做、要用哪些工具、有什麼規則。存起來之後，下次開新視窗只要說觸發詞，不用重新解釋。

例如「抓快電商資料」這個 skill，裡面記錄了登入流程、要抓哪些欄位、整理成什麼格式。說一句，它就自己跑完。我去看其他視窗。

現在有三十幾個 skill，每天用的差不多是固定幾個。

--

每天平均省下的時間大概在 50 到 100 分鐘之間，視任務而定。

有幾個 session 省下更多，例如整套 LINE Bot 功能一個下午做完，手動可能要兩三天。但那是特殊情況，不是常態。

常態是每天省一個小時左右的重複執行時間，這些時間可以用來決定下一步要做什麼、哪些任務要排優先。

這才是並行工作流真正的價值：不是快，是讓你有空間去想，而不是執行。
